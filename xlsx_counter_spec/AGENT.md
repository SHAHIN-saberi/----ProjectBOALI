# AGENT.md — XLSX Symbol Counter

## 1. مأموریت پروژه

این پروژه یک برنامه دسکتاپ سبک برای Windows است که با Python ساخته می‌شود و در نهایت به فایل `.exe` تبدیل می‌شود.

وظیفه اصلی برنامه:

1. دریافت فقط فایل Excel با فرمت `.xlsx` از کاربر.
2. پیدا کردن خودکار ساختار فایل بدون فرض ثابت درباره شماره ردیف/ستون.
3. پیدا کردن ردیف Header حاوی `#CHROM` و `FORMAT`.
4. تشخیص محدوده واقعی داده و ستون‌های واقعی داده، حتی وقتی بین Header و داده جابه‌جایی ستونی وجود دارد.
5. دریافت Symbolهای موردنظر از کاربر به‌صورت پویا و با قابلیت اضافه‌کردن Symbolهای متعدد.
6. شمارش دقیق و case-sensitive/byte-faithful بر اساس مقدار دقیق سلول؛ هیچ نرمال‌سازی محتوایی انجام نشود.
7. شمارش جداگانه سلول‌های خالی و مقادیر ناشناخته/غیرانتخابی.
8. تولید یک فایل `.xlsx` در پوشه‌ای که کاربر انتخاب می‌کند.
9. نمایش پیشرفت، وضعیت پردازش و امکان لغو.
10. رابط کاربری کاملاً فارسی، راست‌چین، ساده، مدرن و کاربردی با فونت Vazir.

**Scope Lock:** هیچ قابلیت جدیدی خارج از این سند بدون درخواست مستقیم مالک پروژه اضافه نشود.

## 2. مشاهده واقعی از فایل نمونه

فایل مرجع بررسی‌شده:

`chro1het - Copy.xlsx`

مشخصات مشاهده‌شده:

- حجم فایل: حدود 193 MB.
- یک Worksheet اصلی با نام: `Filtered_ALL.chr1.phase3_shapei`.
- ابعاد مشاهده‌شده Worksheet: تا `CSS22165`.
- آخرین ستون فیزیکی استفاده‌شده در فایل: `CSS` یعنی 2541.
- Header اصلی در ردیف 253 قرار دارد.
- داده از ردیف 254 شروع می‌شود و تا ردیف 22165 ادامه دارد.
- Header از `A253` با `#CHROM` و در `I253` با `FORMAT` شروع می‌شود.
- اولین نام Sample در `J253` برابر `HG00096` است.
- تعداد نام‌های Sample در Header از J تا CRQ برابر 2504 است.
- در داده نمونه، `T254` مقدار `GT` دارد و اولین Genotype متناظر با Sample اول از `U254` آغاز می‌شود.
- بنابراین در فایل نمونه، داده نسبت به Header به اندازه 11 ستون به راست شیفت شده است.
- بازه `U:CSB` دقیقاً 2504 ستون دارد و با 2504 نام Sample در Header قابل نگاشت است.
- ستون‌های `CSC:CSS` دارای داده‌اند ولی Header نام متناظر برای آنها وجود ندارد؛ این ستون‌ها باید در خروجی حذف نشوند و به‌صورت «بدون نام/ناشناخته» گزارش شوند.
- یک بررسی حداقل 300 ردیف × 300 ستون انجام شد.
- در این محدوده Symbolهای `0|0`, `0|1`, `1|0`, `1|1` مشاهده شدند.
- مقادیر دیگری مانند `0|2`, `2|0`, `2|2` و مقادیر غیر-genotype نیز در ناحیه مورد بررسی وجود داشتند.

### قانون بسیار مهم ناشی از فایل نمونه

ستون «مرجع Excel» باید **ستون فیزیکی سلولی که واقعاً شمارش از آن انجام شده** باشد، نه صرفاً محل نام Sample در Header.

مثلاً برای فایل نمونه:

- نام Sample: `HG00096`
- محل Header: `J253`
- ستون داده واقعی: `U`
- محدوده بررسی نمونه: `U254:U22165`

بنابراین برنامه نباید به‌صورت ثابت فرض کند که `HG00096` یعنی ستون J.

## 3. نیازمندی‌های رابط کاربری

### 3.1 بخش فایل ورودی

- Label فارسی: `فایل اکسل ورودی`
- TextBox راست‌چین برای نمایش مسیر فایل.
- Button: `انتخاب فایل`
- File dialog فقط `.xlsx` را فیلتر کند.
- پس از انتخاب، مسیر کامل فایل در TextBox نمایش داده شود.
- فایل ورودی و فایل خروجی نباید یک فایل یکسان باشند.

### 3.2 بخش Symbolها

کاربر باید بتواند Symbolها را یکی‌یکی وارد کند:

- TextBox راست‌چین.
- Button: `تأیید نماد`
- با تأیید، Symbol به لیست نمادهای انتخاب‌شده اضافه شود.
- TextBox برای Symbol بعدی پاک شود و فوکوس دوباره روی آن قرار گیرد.
- این روند تا زمان فشردن `ساخت فایل خروجی` ادامه دارد.
- تعداد Symbolها محدود به 4 نیست.
- Symbolها باید دقیقاً همان‌طور که وارد شده‌اند جست‌وجو شوند.
- هیچ تبدیل خودکار مانند trim محتوایی، تغییر case، تغییر `|`، تبدیل به عدد، تبدیل Unicode یا Regex انجام نشود.
- Symbol خالی نباید پذیرفته شود.
- تکرار دقیق یک Symbol در لیست باید رد شود.

برای نمایش Symbolهای اضافه‌شده، یک لیست/جدول ساده با دکمه حذف کنار هر مورد مجاز است، چون برای مدیریت مستقیم ورودی لازم است.

### 3.3 بخش مسیر خروجی

- Label: `پوشه خروجی`
- TextBox راست‌چین برای مسیر.
- Button: `انتخاب پوشه`
- فقط Folder انتخاب شود؛ کاربر Save As برای فایل خروجی انجام نمی‌دهد.
- نام خروجی به‌صورت خودکار ساخته شود، ترجیحاً:

`<نام_فایل_ورودی>_شمارش.xlsx`

- در صورت وجود فایل، بدون overwrite خودکار نام یکتا ساخته شود (`_1`, `_2`, ...).

### 3.4 کنترل پردازش

دکمه اصلی:

`ساخت فایل خروجی`

دکمه ثانویه هنگام پردازش:

`لغو پردازش`

در زمان پردازش:

- کنترل‌های ورودی غیرفعال شوند.
- دکمه لغو فعال باشد.
- UI freeze نشود.
- پردازش در Thread پس‌زمینه انجام شود و UI فقط از طریق event/queue به‌روزرسانی شود.
- از `multiprocessing` برای این پروژه استفاده نشود مگر ضرورت فنی اثبات‌شده.

### 3.5 Progress

نمایش موارد زیر:

- Progress Bar
- درصد در صورت امکان
- ردیف جاری
- کل ردیف تقریبی/قطعی در صورت در دسترس بودن
- نام مرحله فعلی، مثلاً:
  - `در حال بررسی ساختار فایل...`
  - `در حال شمارش...`
  - `در حال ساخت فایل خروجی...`
  - `پردازش لغو شد`
  - `با موفقیت انجام شد`

## 5. منطق کشف ساختار Excel

### 5.1 محدودیت مهم

هرگز این موارد hard-code نشوند:

- `row 253`
- `data starts at 254`
- `sample starts at J`
- `last column = CSS`
- `offset = 11`

این‌ها فقط ویژگی فایل نمونه‌اند و باید توسط الگوریتم کشف شوند.

### 5.2 پیدا کردن Header

برنامه باید Worksheet مناسب را پیدا کند. برای فایل‌های معمول این نوع:

- در هر Worksheet قابل بررسی، ردیف‌ها را Streaming اسکن کن.
- ردیفی که `#CHROM` و `FORMAT` را در خود دارد به‌عنوان Candidate Header انتخاب شود.
- اگر چند Candidate وجود داشت، ردیفی انتخاب شود که ساختار Header کامل‌تری داشته باشد و بعد از آن داده معتبر دیده شود.
- اگر هیچ Header معتبر پیدا نشد، پردازش متوقف و پیام خطای فارسی واضح نمایش داده شود.

### 5.3 Sample Headerها

- موقعیت Header `FORMAT` را پیدا کن.
- Sample Headerها از سلول بلافاصله بعد از `FORMAT` تا آخرین Header غیرخالی متوالی استخراج شوند.
- نام Header نباید به‌عنوان تنها مرجع فیزیکی داده فرض شود.

### 5.4 پیدا کردن شروع واقعی داده Sample

در فایل مرجع، در اولین Data Row مقدار `GT` در یک ستون بعدتر قرار گرفته و Sampleها بعد از آن شروع می‌شوند.

الگوریتم پیشنهادی:

1. Data Rowهای اولیه بعد از Header را بررسی کن.
2. بعد از محدوده Metadata/Header، دنبال Field مربوط به FORMAT بگرد:
   - مقدار `GT`
   - یا مقدار شروع‌شونده با `GT:`
3. اگر Marker معتبر پیدا شد، Sample Data از سلول بعدی آن شروع شود.
4. چند Data Row ابتدایی را بررسی کن و ثابت‌بودن محل Marker/شروع Sample را تأیید کن.
5. اگر موقعیت شروع Sample در Data Rowهای مختلف ناسازگار بود، به‌جای حدس‌زدن، خطای ساختاری نمایش بده.
6. اگر Marker قابل تشخیص نبود، fallback محافظه‌کارانه: شروع از اولین ستون بعد از Header `FORMAT`؛ سپس صحت‌سنجی با طول Headerها و وجود Data انجام شود.

### 5.5 Mapping

اگر تعداد Header Sampleها `N` باشد و Sample Data واقعی از ستون فیزیکی `S` شروع شود:

- Header Sample شماره 1 ← Data column S
- Header Sample شماره 2 ← Data column S+1
- ...
- Header Sample شماره N ← Data column S+N-1

این Mapping باید در تمام Data Rowها ثابت باشد.

### 5.6 ستون‌های اضافی بدون Header

هر ستون فیزیکی بعد از انتهای Sample Mapping که در Data دارای مقدار واقعی داشته باشد، باید در گزارش بیاید.

برای آن:

- `نام نمونه/هدر` = `بدون نام`
- `ستون Excel مرجع` = Letter فیزیکی ستون، مثل `CSC`

در فایل نمونه `CSC:CSS` باید در خروجی وجود داشته باشند.

### 5.7 تشخیص پایان Data

- Data Row از اولین ردیف بعد از Header که دارای داده معتبر است آغاز شود.
- پایان Data به‌صورت خودکار با آخرین ردیفی که در ناحیه Data/Source دارای مقدار باشد تعیین شود.
- از `max_row` فقط به‌عنوان راهنمای اولیه استفاده شود؛ صحت آن با داده واقعی کنترل شود.
- اگر ابعاد Worksheet نادرست یا ناسازگار بود، الگوریتم باید بتواند با Streaming scan ادامه دهد.

## 6. تعریف شمارش

### 6.1 Exact Match

اگر کاربر Symbol زیر را وارد کند:

`0|0`

فقط سلولی که مقدار دقیقاً برابر `0|0` باشد، Match محسوب می‌شود.

`0|0:35:99` نباید Match شود.

` 0|0` نباید Match شود.

`0|0 ` نباید Match شود.

`0|O` نباید Match شود.

هیچ regex، substring یا normalization استفاده نشود.

### 6.2 دسته‌ها

برای هر ستون Data واقعی، حداقل این آمار ثبت شود:

1. هر Symbol انتخاب‌شده توسط کاربر، با Count جداگانه.
2. `خالی` برای سلول‌های خالی/None/بدون مقدار.
3. `ناشناخته` برای مقادیر غیرخالی که هیچ‌کدام از Symbolهای انتخابی نیستند.
4. `کل` تعداد سلول‌های بررسی‌شده آن ستون.

### 6.3 مقدارهای ناشناخته

برای اینکه «چیزی که کاربر وارد نکرده» قابل مشاهده باشد، علاوه بر Count تجمیعی `ناشناخته`، مقدارهای ناشناخته دقیق نیز در یک Sheet جزئیات ثبت شوند.

Sheet پیشنهادی: `مقادیر ناشناخته`

ستون‌ها:

- ستون Excel مرجع
- نام نمونه/هدر
- مقدار ناشناخته دقیق
- تعداد
- محدوده بررسی

این Sheet فقط برای مقادیر ناشناخته غیرخالی تولید شود و خالی‌ها در آن به‌عنوان مقدار متنی مستقل تکرار نشوند.

اگر Cardinality ناشناخته بسیار بزرگ شود، معماری نباید تمام File/Rowها را در RAM نگه دارد. در صورت نیاز می‌توان از شمارش مرحله‌ای یا spill-to-disk استفاده کرد، ولی این نباید باعث اضافه‌شدن وابستگی سنگین شود.

## 7. تعریف محدوده Excel

برای هر Data Column، محدوده بررسی باید با آدرس واقعی Excel ثبت شود.

مثال فایل نمونه:

`U254:U22165`

برای هر ردیف خروجی Count، ستون واقعی شمارش‌شده و Range واقعی آن ثبت شود.

### مهم

Range باید بر اساس **ستون فیزیکی Data** ساخته شود، نه ستون Header.

## 9. فناوری و نسخه‌ها

### Python

نسخه هدف پروژه:

`Python 3.13.16`

دلیل: در حال حاضر Python 3.14.8 جدیدترین feature release است، اما Python 3.13.16 آخرین maintenance release کامل سری 3.13 است و برای هدف «کمترین ریسک سازگاری/باگ» انتخاب محافظه‌کارانه‌تری است. سری 3.14 نیز توسط PyInstaller پشتیبانی می‌شود، بنابراین این انتخاب ناشی از سازگاری پایدارتر است نه محدودیت ابزار.

### GUI

- `tkinter`
- `tkinter.ttk`

### Excel Reader/Writer

- `openpyxl`
- Reader: `read_only=True`
- Writer: `Workbook(write_only=True)`
- همیشه `values_only=True` در iteration داده‌های ورودی تا حد امکان.
- هرگز Workbook معمولی read/write برای فایل ورودی بزرگ استفاده نشود.
- هرگز DataFrame کل فایل ساخته نشود.
- `pandas` برای این پروژه استفاده نشود.

openpyxl برای فایل‌های بسیار بزرگ read-only را با مصرف حافظه نزدیک به ثابت ارائه می‌کند و write-only نیز برای تولید داده‌های حجیم طراحی شده است.

### EXE

- `PyInstaller 6.x`، نسخه پایدار موجود در زمان build.
- Build فقط روی Windows 64-bit.
- حالت نهایی ترجیحاً `onefile` و `windowed`.
- در صورت مشکل عملکرد startup، `onedir` به‌عنوان fallback build قابل بررسی است، اما خروجی نهایی پیش‌فرض باید یک EXE باشد.

- `excel_writer.py`: تولید XLSX با write-only.
- `job_runner.py`: Thread، cancel event، progress event و error propagation.
- `ui/*`: فقط Presentation، ورودی و نمایش وضعیت؛ منطق Excel داخل UI نوشته نشود.

## 11. مدیریت حافظه

اصل طراحی:

> RAM باید متناسب با «ابعاد یک Row + Counters + ساختار خروجی کوچک» باشد، نه متناسب با حجم فایل.

قواعد:

- کل Worksheet هرگز در حافظه نگهداری نشود.
- کل Rows هرگز list نشوند.
- کل Cells هرگز dictionary/indexed cache نشوند.
- Counters به‌ازای ستون نگهداری شوند.
- خروجی مستقیماً با write-only تولید شود.
- Workbook ورودی پس از پایان/لغو با `close()` بسته شود.
- از temporary output و rename نهایی استفاده شود تا فایل ناقص به‌عنوان نتیجه نهایی باقی نماند.

برای Counterهای معمولی فقط state لازم نگه داشته شود.

## 14. آزمون‌ها و Acceptance Criteria

### ساختار

- Header در هر ردیف مجاز کشف شود.
- Header نباید به ردیف ثابت وابسته باشد.
- شروع Data نباید به ستون ثابت وابسته باشد.
- Shift بین Header و Data باید تشخیص داده شود.
- ستون‌های trailing بدون Header باید در خروجی دیده شوند.
- اگر mapping ناپایدار باشد برنامه باید خطای ساختاری بدهد، نه نتیجه حدسی.

### شمارش

- Exact match تست شود.
- Symbol `0|0` فقط با `0|0` match شود.
- `0|0:35:99` match نشود.
- Empty از Unknown جدا باشد.
- Symbol با Count=0 هم در خروجی موجود باشد.
- Unknown aggregate موجود باشد.
- Unknown exact values در Sheet جزئیات ثبت شوند.
- Total = Selected Matches + Empty + Unknown.

### خروجی

- برای هر Data Column واقعی حداقل یک رکورد در خروجی وجود داشته باشد.
- ستون فیزیکی واقعی در خروجی ثبت شود.
- Range واقعی، مانند `U254:U22165`، درست ساخته شود.
- Header Sample به Data Column درست map شود.
- Column بدون Header با label `بدون نام` گزارش شود.
- فایل خروجی معتبر و قابل‌افتتاح توسط Excel باشد.

### UI

- تمام UI فارسی.
- RTL.
- Vazir.
- انتخاب فایل.
- انتخاب پوشه.
- افزودن چند Symbol.
- حذف Symbol.
- شروع.
- Progress.
- Cancel.
- Success/Error message.

### تست مرجع

برای جلوگیری از regression، یک fixture کوچک بساز که ساختار فایل واقعی را تقلید کند:

- Header در ردیفی غیر از ابتدای فایل.
- `FORMAT` در Header.
- چند فیلد INFO اضافی بین Header FORMAT و Data FORMAT.
- Sample data با offset نسبت به Header.
- چند ستون trailing بدون Header.
- Symbolهای شناخته‌شده و ناشناخته و Empty.

یک smoke/manual benchmark روی فایل اصلی 193MB نیز انجام شود، ولی آن فایل وارد Git نشود.
